# 口述史馆 · 检索字幕

为口述史馆的单期访谈原片维护「检索字幕」：上传原片 WebVTT 与剪辑 CSV，按剪辑表拼接片段并逐次校订被剪口截断的字幕，发布后按版号下载完整 WebVTT。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。数据库保存在名为 `oral-history-data` 的卷里，重启容器后已发布版本仍可原样下载。

本地开发：

```bash
python3 -m pip install -r requirements.txt
ORAL_HISTORY_DB=./data/oral_history.db flask --app app.wsgi run --debug
```

## 使用流程

1. **上传单期原片**：一个 WebVTT + 一个剪辑 CSV。
   - CSV 列：`片段号,原片起毫秒,原片止毫秒`（也接受 `fragment_no,start_ms,end_ms`；无表头时按此顺序读取）。
   - 行序即拼接顺序；片段号在表内唯一；**同一原片时段允许被多个片段号重复取用**。
2. **同一期访谈试剪几个版本**：原片 WebVTT 只需传一次。首页会显示当前原片（含原字幕总数），之后**只交剪辑 CSV 就能建稿**。
   - 建稿按**页面所示的那份原片**取段：即使另一个窗口随后上传了别的原片，本次提交仍用页面上看到的原片。
   - 每份原片登记一次，并建立**共用的时段索引**（与首次建稿在同一事务生效）；这份原片的各个草稿共用该索引。
3. **预览**：每一条字幕出现都同时显示对应的**原片时码**与**节选时码**。
   - 整条落在片段内的字幕标记为「整条保留」，沿用正文，无需录入。
   - 被剪口截断的字幕标记为「剪口截断」，须**逐次**录入保留文字或标为删除；同一片段重复出现时各算一次。
4. **发布**：所有剪口出现都处理完才能发布；发布成功后生成新版本号，可下载完整 WebVTT。
5. **更换剪辑表**：重新上传即建立新草稿，每一次出现都会**重新计算节选时码**。

## 规则要点

- **校订沿用**：仅当「片段号 + 原字幕正文 + 保留的原片范围」三者完全一致时，才沿用上一版校订；剪辑表或原片范围一变即需重新录入。
- **时段索引**：索引建好后，建稿、打开草稿、保存和发布都只读取与选段相交的字幕正文，不为每个选段遍历全片字幕；从剪口前开始、延续进片段的字幕也会被选中。
- **失败照旧**：校验或写入失败时，当前草稿和可复用的原片保持不变（建稿事务整体回滚）。
- **旧数据兼容**：已有 SQLite 卷中的旧草稿照常编辑、发布；旧原片在首次复用时自动补建时段索引。
- **旧页面拒绝**：上传新剪辑表或发布成功后，先前打开的草稿页提交校订/发布会被拒绝（HTTP 409），提示刷新后重新录入。
- **发布原子性**：有未处理剪口、版本冲突或写入失败时不会产生新版本；已发布版本存在 SQLite 中，重启后按版号原样下载，原片也仍可沿用。

## 项目结构

```
app/core.py         领域逻辑：时码、WebVTT、剪辑 CSV、出现计算、校订继承、SQLite
app/app.py          Flask 路由
app/templates/      页面模板
app/static/style.css
tests/              单元测试与网页流程测试
examples/           示例 WebVTT 与剪辑 CSV
```
